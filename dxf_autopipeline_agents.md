### BA-001: Маппинг цветов HATCH → тип функциональной зоны
Функциональные зоны на генплане — это закрашенные области (HATCH) разных цветов. Каждый цвет означает тип зоны (дворовая территория, ОТОП, дороги и т.д.). Тебе нужно:
1. Собрать у ГИП/архитекторов полный справочник: цвет (ACI code) → тип зоны

3. Результат — таблица в Excel: ACI Color | RGB | Тип зоны | Проект | Комментарий
4. Для этого от SA ты получишь скрипт, который автоматически извлекает цвета из DXF

### BA-002: Параметры системы координат (CRS)
DXF-файлы используют локальную систему координат (метры). Для отображения в EverGIS нужно перевести в WGS84. Тебе нужно:
1. Узнать у проектировщиков, в какой системе координат они работают (МСК-50? Локальная СК?)
2. Получить параметры: proj-строку или опорные точки (координаты в DXF → координаты в WGS84)
3. Проверить текущую настройку из сервиса (MSK_CRS в .env) — совпадает ли

### BA-003: Реестр целевых карт EverGIS
Для автоматической загрузки сервис должен знать, в какую карту EverGIS грузить данные каждого проекта. Тебе нужно:
1. Получить список активных проектов с генпланами

3. Определить naming convention для слоёв

### Ключевые находки из ревью:
1. MULTILEADER (слой 0) и MTEXT (ОГП_НУМЕРАЦИЯ) на разных слоях — код берёт только один
2. MTEXT "Дом N" не попадают внутрь зданий (0/64) — они в стилобатах
3. MULTILEADER указывают на HATCH (83%), а не на здания — это номера зон БиО
4. 4 из 7 ACAD_TABLE пропускаются — код ищет только «схем», не «дом»
5. "Дом 1" × 3 локации в одном словаре — перепутаны атрибуты
6. Грязные заголовки (pipe-formatting не чистится)
7. Ложная дедупликация текста (1010→10)

### Архитектурное решение:
Не чинить process_combined, а написать 3 новых модуля:
- table_parser.py — парсинг ACAD_TABLE с разделением по локациям
- building_matcher.py — привязка зданий через стилобаты
- zone_matcher.py — привязка HATCH через MULTILEADER
Плюс оркестратор auto_pipeline.py.
